# C-Visualizer 语义模型（SEMANTIC_MODEL）

> **本文档是解释器语义行为的规范来源（normative）。** Checker 与 Interpreter 必须共同遵守；
> 两者不一致视为缺陷。版本：v1.1.0（Semantic Conformance Hardening）。
> 教学子集的语言范围以 [SUPPORTED_C.md](SUPPORTED_C.md) 为准；本文只定义「已支持部分的语义」。

## 1. 总原则

1. **教学可信优先**：宁可编译期拒绝、运行期报错，也不给出「看似确定的错误结果」。
2. **Checker 与 Interpreter 一致**：静态可见性模型 = 运行时作用域栈；静态类型规则 = 运行时收敛规则。
3. **与 C 的偏差必须显式**：所有与 ISO C 不同的行为都在 §10 列出并说明理由。
4. **不模拟的 UB 不产生确定结果**：检测到的求值顺序问题在编译期拒绝（E_UB）。

## 2. 作用域模型（Lexical Scope）

### 2.1 结构

静态检查使用 `TypeEnvironment`（词法作用域栈），运行时使用 `Scope` 栈，二者层级一一对应：

```
Global Scope（全局变量 + 函数名表）
  └─ Function Scope（形参 + 函数体顶层声明）
       └─ Block Scope（{ ... }）
            └─ For Scope（for (int i = ...) 的 init 声明）
                 └─ Nested Block / Loop Body / Switch Body ...
```

- **变量查找**：从最内层作用域向外逐层查找，命中即止（同名内层遮蔽外层）。
- **声明**：只加入当前（最内层）作用域。
- **退出块**：弹出该层作用域，其中的变量不再可见。
- **同一作用域重复声明**：编译错误 `E_DECL`。
- **外层/内层同名（shadowing）**：合法，两个变量完全独立。

### 2.2 各构造的作用域规则

| 构造 | 规则 |
| --- | --- |
| 函数体 | Function Scope；形参与函数体顶层声明同层（`int f(int x) { int x; }` 报 E_DECL，与 C 一致） |
| 复合语句 `{}` | 进入时压栈 Block Scope，退出时弹出 |
| `for (int i = ...)` | init 声明位于专属 For Scope，**仅在 for 语句内可见**（条件 / update / body 均可见，循环外不可见） |
| `for (i = 0; ...)`（表达式 init） | 不引入新声明；i 必须已在作用域内 |
| while / do-while body | body 若是块则 Block Scope；非块单语句不引入声明 |
| if / else 分支 | 各分支独立作用域（若是块） |
| switch body | **整个 switch 体是一个 Block Scope**（C 语义：case 标签不引入新作用域，各区段声明共享同一层） |
| 函数名 | 全局唯一（全局表）；与变量名空间不冲突（C 中函数与变量同命名空间，教学简化：函数名单独一张表） |
| 全局变量 | Global Scope；与函数名可同名（分属两表）；互相遮蔽时变量优先 |

### 2.3 声明点（point of declaration）

- 名字自其**声明符结束**起可见：`int x = x;` 中初始化式引用的是新声明的 x 自身
  （类型一致，编译通过；运行时读取报 `E_UNINIT_READ`，与 C 的 indeterminate value 对应为教学错误）。
- 一条语句多声明符按顺序处理：`int a = 1, b = a;` 合法（b 的初始化式可见 a）。

### 2.4 goto 与作用域

运行时 goto 以信号冒泡实现，支持矩阵（**保守子集**）：

| 场景 | 支持 | 说明 |
| --- | --- | --- |
| 同一语句序列内前向 goto | ✅ | 跳转目标之后的语句顺序执行 |
| 同一语句序列内后向 goto | ✅ | 重新经过声明时复用存储单元并重置为未初始化，随后初始化重新进行 |
| goto 跳出到外层序列（含跳出循环 / 块 / switch） | ✅ | 冒泡过程中块作用域正常弹出 |
| 前向 goto 跳过声明，之后引用该变量 | ✅（行为对齐 C） | **被跳过的声明在跳转时补创建变量并置为未初始化**（C：块作用域覆盖整块，跳过初始化 = indeterminate）；读取报 `E_UNINIT_READ` |
| **goto 跳入嵌套块 / 兄弟块**（目标 label 不在 goto 所在序列到函数顶层的祖先链上） | ❌ 编译错误 `E_LABEL` | 运行时按序列冒泡无法进入未打开的块；教学安全取舍（ISO C 合法，本项目明确不支持，见 §10） |
| **goto 到 if/循环单语句分支或 case 语句内的标签** | ❌ 编译错误 `E_LABEL` | 标签不在任何可跳转序列顶层（运行时无法命中；ISO C 合法，教学取舍同上） |

## 3. 类型与运行时收敛（Runtime Coercion）

### 3.1 存储表示

| C 类型 | 单元表示 | 备注 |
| --- | --- | --- |
| `int` | 32 位有符号整数（`Math.trunc(v) \| 0`） | 溢出环绕，不做 UB 检测（与典型实现一致） |
| `char` | 0～255（`v & 0xff`） | 教学简化：不区分 signed/unsigned char；超出 0～255 的值按低 8 位收敛 |
| `float` / `double` | JS double | 不区分精度；显示最多 6 位有效数字 |
| `T *` | 目标地址（整数；0 = NULL） | 一层指针 |

### 3.2 统一收敛规则（`coerceRuntimeValue(value, targetType)`）

**所有**「值进入对象」的边界必须经过同一实现（`src/core/coercion.ts`）：

| 边界 | 收敛目标 |
| --- | --- |
| 变量初始化（标量） | 声明类型 |
| 普通赋值 `=` / 复合赋值最终写回 | 左值类型 |
| 函数实参 → 形参绑定 | 形参类型 |
| `return expr` 的值 | **函数返回类型** |
| 数组初始化列表元素 | 数组元素类型 |
| 数组元素赋值 `a[i] = v` | 数组元素类型 |
| 标量单元写回（writeCell 内部） | 单元类型 |

数值转换矩阵（数值 ↔ 数值均允许隐式转换）：

| 目标 \ 源 | int | char | float/double | pointer |
| --- | --- | --- | --- | --- |
| int | 恒等 | 符号值即整数 | 截断（`trunc`） | 非法（仅常量 0 视为 NULL，检查器控制） |
| char | `& 0xff` | 恒等 | 截断后 `& 0xff` | 非法 |
| float/double | 数值 | 数值 | 恒等 | 非法 |
| pointer | 仅常量 0 | — | — | 检查器已保证 pointee 一致；运行时原值传递 |

### 3.3 函数返回

- **静态**：`return expr` 的表达式类型必须与返回类型**赋值兼容**（数值互转允许；数组 / 字符串
  按赋值兼容规则拒绝；`void fn` 带 `return expr` 报错；非 void 裸 `return;` 报错）。
- **运行时**：返回值在离开函数前**强制收敛到函数返回类型**：
  - `int f() { return 1.9; }` → 调用方得到 int 1；
  - `char f() { return 300; }` → 300 & 0xff = 44；
  - `double f() { return 3; }` → 运行时类型为 double 3。
- main 隐式返回 int 0（C99 同）。

### 3.4 参数传递

按值传递；实参值**在绑定到形参前**收敛到形参类型（`void f(int x)` 调 `f(1.9)` → x 为 int 1）。
收敛与赋值共用 §3.2 的同一实现，不依赖存储单元写回的偶然行为。

### 3.5 算术常规转换（usual arithmetic conversions，教学简化）

- 任一侧为 float/double → 结果 double；
- 否则（int / char）→ 结果 int；
- 比较与逻辑运算结果为 int（1/0）；
- `%` 仅整型；整数除法与取模向零截断（`-7/2 == -3`，`-7%2 == -1`）。

## 4. 控制流合法性（静态检查）

Checker 维护循环 / switch 上下文深度（函数体遍历期间）：

- `break` 合法 ⇔ **loopDepth > 0 或 switchDepth > 0**（就近原则：运行时跳出最近的循环或 switch）；
- `continue` 合法 ⇔ **loopDepth > 0**（switch 不提供 continue 上下文）；
- 违反 → 编译错误 `E_TYPE`（「break 只能出现在循环或 switch 内」/「continue 只能出现在循环内」）。
- 函数边界重置上下文（函数体内顶层的 break/continue 非法，即使调用点在循环内）。

### 4.1 break / continue 的运行时归属展示

解释器维护可中断构造栈（loop / switch）：

- `break` 的控制流事件 `from` 取**栈顶最近的可中断构造**：switch 内的 break 显示
  「跳出 switch」，循环内的 break 显示「跳出循环」；
- `continue` 只作用于最近的循环，事件标注真实循环类型（while / do-while / for）。

## 5. 初始化语义（Storage Duration Policy）

| 存储期 | 标量无初始化式 | 数组无初始化列表 | 带初始化式/列表 |
| --- | --- | --- | --- |
| **全局（静态存储期）** | **零初始化**（int 0 / double 0.0 / char 0 / 指针 NULL） | **全部元素零初始化** | 初始化式求值后按 §3.2 收敛写入（必须是常量表达式，检查器保证） |
| **局部（自动存储期）** | 未初始化：读取报 `E_UNINIT_READ` | **全部元素未初始化**：任一元素读取报 `E_UNINIT_READ` | 标量：求值 + 收敛写入；数组：前缀逐元素收敛写入，**其余元素零初始化**（`{}` 即全 0） |

- 初始化策略在声明路径中**显式传参**（`storage: 'static' | 'auto'`），全局与局部不共用「声明即置 0」路径。
- 后向 goto 重新经过带初始化式的声明 → 重新初始化；重新经过无初始化式的声明 → 回到未初始化。

## 6. 求值顺序与副作用（UB 检测）

### 6.1 解释器实际顺序（仅用于良定义程序的展示）

- 二元运算：先左后右；
- 赋值：先右值后左值地址计算（结果与顺序无关的程序不受影响）；
- 函数实参：从左到右；
- `&&` / `||`：短路（左侧结果确定后跳过右侧，有序列点）。

### 6.2 静态 UB 检测（保守，宁可放过不误杀）

**单位**：完整表达式（表达式语句 / 声明初始化式 / 条件 / return 值 / switch 判别式 / for update）。
**区域**：完整表达式内，`&&` / `||` 的左右两侧互相隔离（序列点）；其余部分属同一区域。

对每个区域内统计每个变量（标识符）的出现：

- **R1（双写）**：同一变量的**写副作用**出现 ≥ 2 次 → `E_UB`。
  例：`i++ + i++`、`i = i++`、`f(i++, i++)`。
- **R2（读写竞争）**：某变量存在写副作用，且该变量在区域内还有**其他出现**（读或写）→ `E_UB`。
  例：`i++ + i`、`a[i] = i++`、`f(i++, i)`、`a[i++] = i`、`f(i) + i++`。
- **赋值豁免**：赋值（含复合赋值）**目标变量自身的写**与该赋值左/右子树中同名的**纯读取**视为
  有序（C11：赋值副作用 sequenced after 左右操作数的值计算）：
  `x = x + 1`、`x += x` 合法；但豁免不覆盖**另一个写**：`i = i++`、`x = (x = 2)` 仍为 R1。
- **下标 / 解引用地址部分不豁免**：`a[i] = i++` 中下标 i 的读取与右侧 i++ 的写竞争 → R2
  （正确：二者无序列点）。
- 函数调用不单独视为变量写；实参之间、实参与调用外围同区域分析（参数间求值顺序 unspecified，
  同名冲突即拒绝）。函数体内部对外部全局变量的副作用无法静态可见，**不检测**（§6.3）。

判定结论对照（C11 严格对照，非凭感觉）：

| 表达式 | C 标准 | 本项目 |
| --- | --- | --- |
| `i++ + i++` | UB | 编译错误 E_UB |
| `i = i++` | UB | 编译错误 E_UB |
| `i++ + i` | UB | 编译错误 E_UB |
| `f(i++, i++)` | UB | 编译错误 E_UB |
| `f(i++, i)` | unspecified（实参顺序不定） | 编译错误 E_UB（保守） |
| `a[i] = i++` | UB | 编译错误 E_UB |
| `a[i++] = i` | UB | 编译错误 E_UB |
| `a[i++] = 1` | 良定义 | 通过 |
| `x = x + 1` | 良定义 | 通过 |
| `x = x++` | UB | 编译错误 E_UB |
| `x += x` | 良定义 | 通过 |
| `i++ && i++` | 良定义（&& 有序列点） | 通过（左右分区域） |
| `i++ , j++`（逗号） | 良定义 | 不支持逗号（转换层拒绝） |
| `f(i) + i++` | UB（若 f 读取 i；不可见） | 编译错误 E_UB（保守） |

### 6.3 本轮不覆盖（SUPPORTED_C 同步声明）

- 函数体内部修改全局变量与调用点表达式的作用：不检测（跨函数分析超出本轮范围）；
- 整数溢出环绕：不检测（与典型实现一致的环绕）；
- 除法 / 取模除零：**运行时**错误（非编译期常量传播）；
- 未初始化读取：运行时错误（教学策略）。

## 7. E_INTERNAL 使用纪律

`E_INTERNAL` 仅表示**解释器自身缺陷**（invariant violation）。用户可触发的路径必须转为：

- 静态可判定 → 编译错误（本版本消除了「goto 跳入嵌套块」这一用户可触发 E_INTERNAL）；
- 动态才可判定 → 明确的运行时错误码（E_UNINIT_READ / E_UNDEF_VAR / ...）。

回归保障：`compile(source).ok === true` 的程序集执行后不得出现 `E_INTERNAL` 步骤（tests 语义扫描）。

## 8. 步骤 / 快照不变量

- 快照可序列化；每步深拷贝；nextAddress 单调递增（保证确定性回放）；
- 作用域栈的弹出在终止步骤（program-end / runtime-error / halt）前保持现场（教学需要）；
- 控制流事件的 from/loopType 必须与实际控制流构造一致（§4.1）。

## 9. 差分测试（Differential Testing）

- 语料：限定 **defined behavior** 的程序集（§6 规则保证无 UB 表达式；无未初始化读取；
  无溢出依赖；无浮点精度依赖——浮点仅用可精确表示的字面量与加减）；
- 参考：gcc / clang（存在则用）；比较 stdout 与 main 返回值（通过 printf 输出）；
- 环境无编译器 → 整套差分测试 graceful skip，并在输出中记录
  `DIFFERENTIAL_COMPILER_UNAVAILABLE`（CI ubuntu-latest 自带 gcc，会实跑）。

## 10. 与 ISO C 的有意差异（教学简化汇总）

| # | 差异 | 理由 |
| --- | --- | --- |
| 1 | 未初始化读取 → 运行时错误（标准：indeterminate value） | 帮助学生发现忘记初始化 |
| 2 | goto 跳入嵌套块 / 兄弟块 → 编译错误（标准：合法） | 信号冒泡实现无法打开未进入的块；教学安全 |
| 3 | 参数求值顺序固定从左到右（标准：unspecified） | 仅展示用途；同名冲突已被 E_UB 拒绝，结果不受顺序影响 |
| 4 | char 为 0～255 无符号字节（标准：实现定义符号性） | 简化；与「char 显示为字符」配合 |
| 5 | 整数溢出环绕不警告（标准：UB） | 与典型实现一致；不追求完整 UB 引擎 |
| 6 | 函数不要求先声明后使用（C99 起标准要求） | 降低初学者负担 |
| 7 | float 与 double 同为双精度（标准：float 精度更低） | 简化 |
| 8 | goto 跳过声明后读取 → E_UNINIT_READ（标准：indeterminate value） | 对齐教学错误策略 |
| 9 | 保守 UB 拒绝：`f(i++, i)`、`f(i) + i++` 等 unspecified 情况也拒绝 | 教学工具不能展示「顺序敏感却看似确定」的结果 |
