## 二、本轮问题清单

1. **【核心】源码修改后旧 runResult 仍被当作当前结果**（`src/App.tsx`）：
   编辑器 `onChange` 仅 `setSource(v)`；右侧变量/内存/调用栈/控制流/输出/当前执行行/时间轴
   全部继续展示上一次运行的数据，且播放控制仍可操作旧状态——教学语义误导（最高优先级）。
2. **当前执行行高亮不失效**：`currentLine={cur ? cur.line : null}` 不感知源码变化，
   旧行号会错误映射到已修改源码的某一行。
3. **编译失败后的状态语义未定义清楚**：现行实现直接清空 runResult，
   「旧结果保留但明确标记为旧结果」的推荐语义未实现（本轮统一设计）。
4. **加载示例后**：`loadExample` 已清空 runResult/currentStep/playing/compileErrors（现状正确），
   但缺 dirty 维度，需保证口径一致。
5. **CallStackPanel 冗余三元**（`src/ui/Panels.tsx:179`）：`frames[idx + 1] ? f.callLine : f.callLine` 两侧相同。
6. **v1.0.1 Release Notes 相对链接**：指向 tag 快照中不存在的文件。
7. **Repository homepage 为空**。

## 三、修复方案

### 3.1 Dirty Source 状态（核心）

新增纯逻辑模块 `src/ui/run-state.ts`（与既有 `ui/playback.ts` 同风格）：

- `nextDirtyState(prev, event)`：`edit → true`；`run-success → false`；`run-fail → 保持`；
  `load-example → false`
- `shouldDisablePlayback({busy, parserError, sourceDirty, total})`：五项播放控制
  （上一步/下一步/播放/重新开始/时间轴）+ 键盘快捷键（←/→/空格）的统一禁用判定
- `shouldDisableRun({busy, parserError})`：运行按钮保持可用（dirty 不影响），规则显式化避免按钮状态矛盾
- `visibleCurrentLine(sourceDirty, cur)`：dirty 时返回 `null`（旧行号不得映射到已修改源码）
- `isStaleResult(sourceDirty, runResult)`：`dirty && 旧结果存在` → 显示 stale 横幅

`src/App.tsx` 接入：

- 编辑器输入：`setSource(v)` + `sourceDirty → true` + `setPlaying(false)`
- 运行成功：`setRunResult(result); setCurrentStep(0); sourceDirty → false`
- **编译失败**：显示 compileErrors；**保留旧 runResult（继续标记为旧结果）**，sourceDirty 不变，
  播放控制因 dirty 禁用——旧结果不会看起来像新结果
- 加载示例：完整上下文切换——`runResult = null; currentStep = -1; playing = false;
  compileErrors = null; sourceDirty = false`，等待重新运行

### 3.2 Stale Result 横幅

`sourceDirty && runResult` 时显示（`role="status"`，不阻塞编辑器）：

> ⚠ 源码已修改，当前可视化结果来自上一次运行，请重新运行。［重新运行］

- 文字明确「来自上一次运行」，不依赖颜色传达信息；按钮直接调用 `handleRun`
- 旧结果继续显示供参考，但播放控制全部禁用

### 3.3 CallStackPanel 小修

`frames[idx + 1] ? f.callLine : f.callLine` → `f.callLine`（行为不变）；
顺手检查该区域其余表达式，不做其他重构。
