# P12 — v1.1.0 Semantic Conformance Hardening（设计文档）

> 任务：提高 C 教学解释器的语义正确性、一致性、可维护性与可信度。
> 语义规范见 [SEMANTIC_MODEL.md](SEMANTIC_MODEL.md)（先读它，本文是工程实现设计）。
> 状态：执行中（2026-09-22 起）

## 1. 当前语义架构问题（审计结论）

审计基线：main @ 335fb53（v1.0.2），278 项测试全绿。以下问题全部以实际代码确认为准：

### P1 静态作用域 ≠ 运行时作用域
`src/core/check.ts` 的 `collectLocalDecls` 把函数体**全部**声明收集进一个扁平
`Map<string, CType>`（预置全局 + 形参），语句遍历时统一查这个 Map：
- 块内声明在块外仍「可见」（静态通过）→ `int main() { { int x = 10; } x = 20; }`
  静态通过、运行时才报 `E_UNDEF_VAR`；
- `for (int i...)` 之后使用 i 同样漏报。
而运行时（`interpreter/index.ts` 的 `Scope` 栈 + `findVariable`）是正确的块作用域。
**检查器比解释器宽松 → 一致性破损。**

### P2 返回值不按函数返回类型收敛
- Checker 的 `collectReturns` 只查「有无值」，不查类型兼容；
- 运行时 `ReturnSignal` 直接携带 RuntimeValue 上抛，`callFunction` 原样返回：
  `int f() { return 1.5; }` 的调用点拿到 double 1.5（参与表达式运算时类型错误）。
- 参数绑定依赖 `writeCell` 的收敛（偶然正确，规则分散）。

### P3 break / continue 无静态上下文检查
`checkStmt` 对二者直接放行；函数体顶层的 `break;` 静态通过，运行时信号泄漏成
`E_INTERNAL`（用户可触发）或未定义行为展示。同时 `execBreak` 的控制流事件硬编码
`from: 'loop'` —— switch 里的 break 也显示「跳出循环」（展示错误）。

### P4 初始化语义不分存储期
`declareArray`（interpreter/stmt.ts）无条件「分配即全 0」：
- 局部 `int a[5];` 被错误地零初始化（C：未初始化）；
- 全局 `int g;` 无初始化式 → 单元 `null`，读取报 `E_UNINIT_READ`（C：静态存储期必为 0）。
两条路径共用同一「置 0」逻辑，没有 storage kind 概念。

### P5 未定求值顺序被解释为确定结果
二元「先左后右」、实参「从左到右」被固化为确定输出：`i++ + i++`、`f(i++, i++)`
等 UB 程序得到看似可信的结果 —— 与「教学工具不能误导」直接冲突。

### P6 goto 的一个用户可触发 E_INTERNAL
label 位于嵌套块内而 goto 在外层时（`goto L; { L: ; }`），`collectLabels`
静态放行；运行时 GotoSignal 一路冒泡出函数体 → `callFunction` 抛
`E_INTERNAL: goto 目标标签解析失败`。属于「检查器应拦截」类。

## 2. Scope Checker 设计

新模块 `src/core/scope-env.ts`：

```ts
export class TypeEnvironment {
  pushScope(kind): void          // 进入块/for/switch/函数体
  popScope(): void               // 退出（含越界保护）
  declare(name, type): boolean   // 当前作用域；已存在同名 → false（调用方报 E_DECL）
  hasInCurrentScope(name): boolean
  lookup(name): CType | undefined // 由内向外；命中即止
  get currentDepth(): number
}
```

`check.ts` 重构：
- 删除 `collectLocalDecls` 与扁平 env；`Ctx.env` 替换为 `TypeEnvironment`；
- 语句遍历同步维护栈：`block` → push/pop；`for` 且 init 为 var-decl → 专用 scope
  （init + condition + update + body 共享）；`switch` → body 整体一个 scope；
  if/else 分支、循环 body 若为 block 由 block 自身管理；
- 声明顺序语义：声明符依次入栈后再检查其初始化式（`int x = x;` 类型一致、编译过、
  运行时报 E_UNINIT_READ）；
- goto 合法性：遍历时对每个语句序列记录「祖先链」，label 记录所在序列；goto 要求
  label 序列是其祖先链前缀（允许跳出，禁止跳入嵌套/兄弟块）→ 否则 `E_LABEL`。

独立单元测试 `tests/scope-env.test.ts`（push/pop/declare/lookup/shadow/redecl）。

## 3. Runtime Coercion 设计

新模块 `src/core/coercion.ts`：

```ts
coerceRuntimeValue(value: RuntimeValue, target: CType): RuntimeValue
// int: Math.trunc|0；char: &0xff；float/double: 原值；pointer: 原值（类型由检查器保证）
```

接线（替换所有分散的 `Math.trunc | 0` / `& 0xff`）：
1. `Interpreter.writeCell` → 内部走 coercion（`coerceToCell` 改为薄封装）；
2. `callFunction` 形参绑定：显式 `coerceRuntimeValue(args[idx], p.type)` 后写单元；
3. `execStmt('return')`：`coerceRuntimeValue(value, i.currentFn.returnType)` 后抛信号
   （main 隐式 0 已是 int）；
4. `declareArray` 初始化列表元素：统一 `coerceRuntimeValue(val, elemType)` 写入
   （删除两处内联截断）。

## 4. Control-flow legality 设计

Checker：`Ctx` 增加 `loopDepth` / `switchDepth`（函数体内遍历传递，进函数重置）：
- `break`：`loopDepth + switchDepth === 0` → `E_TYPE`「break 只能出现在循环或 switch 内」；
- `continue`：`loopDepth === 0` → `E_TYPE`「continue 只能出现在循环内」。

运行时展示：`Interpreter.breakableStack: { kind: 'loop' | 'switch'; loopType?: 'while'|'do-while'|'for' }[]`
由 execWhile/execDoWhile/execFor（push 'loop'）/ execSwitch（push 'switch'）维护，
try/finally pop：
- `execBreak` 事件 `from` = 栈顶 kind；描述「跳出 switch / 跳出循环」；
- `execContinue` 事件 loopType = 自栈顶向下第一个 loop 的 loopType。

## 5. Initialization semantics 设计

`Interpreter.currentStorage: 'static' | 'auto'`：
- `run()` 执行 globals 时置 `'static'`；`callFunction` 进入任意函数（含 main）置 `'auto'`；
- `execVarDecl` / `declareArray` 读取该标志作为初始化策略：
  - 无初始化式标量：static → 写 0（按类型零值）；auto → 保持 null（未初始化）；
  - 无初始化列表数组：static → 全元素零；auto → 全元素 null（未初始化）；
  - 带初始化式/列表：求值 + coercion 写入；数组剩余元素**始终零初始化**（含 `{}`）；
  - 后向 goto 重新执行声明：复用单元，按同一策略重置。
- `values.push` 的假值占位（数组 `{type: elem, value: 0}`）改为如实反映
  （未初始化元素 → null，descVarDecl 已支持 null 展示）。

**行为修正（CHANGELOG 记录）**：局部 `int a[5];` 从「全 0」改为「未初始化」；
全局 `int g;` / `int a[5];` 从「读取报 E_UNINIT_READ」改为「零初始化」。
受影响旧测试同步更新（tests/array.test.ts「声明即全 0」等）。

## 6. UB / unspecified evaluation policy

新模块 `src/core/side-effects.ts` + 编译错误码 `E_UB`：
- `checkFullExpr(expr, report)`：按 SEMANTIC_MODEL §6.2 的区域/规则（R1 双写、
  R2 读写竞争、赋值豁免、&&/|| 分区）分析完整表达式；
- 接入点：表达式语句、声明初始化式/列表元素、if/while/do-while/for 条件、for update、
  return 值、switch 判别式；
- 错误消息含变量名与教学建议（「该表达式在 C 中存在未定义行为，不应依赖求值顺序」）。
