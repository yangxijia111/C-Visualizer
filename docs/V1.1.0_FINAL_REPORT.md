## 【Semantic Fixes】（每项：根因 → 修复方式）

### 1. 静态作用域 ≠ 运行时作用域
- **根因**：`check.ts` 的 `collectLocalDecls` 把函数体全部声明收集进扁平
  `Map<string, CType>`（预置全局 + 形参）——块内声明跨块「可见」，静态检查比
  运行时（正确的 Scope 栈）宽松，导致块外使用变量漏报到运行时。
- **修复**：删除扁平 env；新增 `src/core/scope-env.ts`（TypeEnvironment 作用域栈，
  独立单元测试 10 项）；`checkStmt` 遍历同步 push/pop（block / for 专属 / switch
  单层 / if-else 分支）；声明点语义按声明符顺序入栈后再查初始化式。
  任务书案例 1–6 全部达标（案例 1/4 从「运行时错误」变为**编译错误 E_UNDEF_VAR**）。

### 2. 函数返回类型未转换
- **根因**：Checker 的 `collectReturns` 只查「有无值」；运行时 `ReturnSignal`
  直接携带 RuntimeValue 上抛，`int f(){return 1.9;}` 的调用点拿到 double。
- **修复**：`execStmt('return')` 在抛信号前 `coerceRuntimeValue(value, fn.returnType)`；
  Checker 新增 return 表达式与返回类型的赋值兼容检查（数值互转允许）。

### 3. break / continue 无静态检查 + 展示错误
- **根因**：`checkStmt` 对二者直接放行（无上下文）；`execBreak` 硬编码
  `from: 'loop'`，switch 内 break 也显示「跳出循环」。
- **修复**：Checker 维护 loopDepth / switchDepth（函数边界重置）；
  Interpreter 新增 breakableStack（循环携带类型 / switch），break 事件 from 取栈顶、
  continue 标注真实循环类型。任务书十二的 4 组案例全部按预期。

### 4. 初始化语义不分存储期
- **根因**：`declareArray` 无条件「分配即全 0」，且全局标量无初始化式时单元为
  null（读取报错）——与 C 的静态存储期零初始化相反，局部数组又误初始化。
- **修复**：`Interpreter.currentStorage`（执行全局 = 'static'，进函数 = 'auto'）；
  声明路径显式读取策略（见【Initialization】）。

### 5. 未定求值顺序被解释为确定结果
- **根因**：解释器固化解法顺序（二元先左后右、实参从左到右），UB 程序得到
  「看似可信」的确定输出。
- **修复**：新增 `src/core/side-effects.ts` 完整表达式副作用区域分析（E_UB 编译
  拒绝），规则见【Undefined / Unspecified】。

### 6. goto 的用户可触发 E_INTERNAL
- **根因**：label 在嵌套块内而 goto 在外层时，`collectLabels` 静态放行；运行时
  GotoSignal 冒泡出函数体 → `E_INTERNAL: goto 目标标签解析失败`。
- **修复**：静态「语句序列祖先链」校验（跳入嵌套块/兄弟块/case 体/if 单语句
  分支 → 编译错误 E_LABEL）；前向跳过的顶层声明补创建为未初始化。

## 【Scope Model】

| | 旧（v1.0.2） | 新（v1.1.0） |
| --- | --- | --- |
| Checker 数据结构 | 扁平 `Map`（全局+形参+全函数声明） | `TypeEnvironment` 作用域栈（global→function→block/for/switch） |
| 声明归属 | 全函数可见 | 只进当前层；退出块即不可见 |
| 重复声明 | 按 Set 链近似块级 | 精确同层判定（形参与顶层同层） |
| for init 变量 | 循环外仍可见（静态） | 仅 for 内可见，超出 → E_UNDEF_VAR |
| switch 体 | 每个 case 各自一层 | 单一块作用域（C 语义） |
| 声明点 | 无模型 | `int x = x;` 合法，运行读报 E_UNINIT_READ |
| 与运行时一致性 | 不一致（静态更宽松） | 层级一一对应，17 项回归测试锁定 |

## 【Runtime Coercion】统一规则

`src/core/coercion.ts` 的 `coerceRuntimeValue(value, target)` 是唯一实现：

- int：`Math.trunc(v) | 0`；char：`v & 0xff`；float/double：数值不变；
  pointer：值不变（类型检查器保证 pointee 一致）。

接入边界（全部同源，无分叉实现）：

| 边界 | 实现位置 |
| --- | --- |
| 标量初始化 / 赋值 / 复合赋值写回 | `Interpreter.writeCell` → `coerceToCell`（薄封装） |
| 形参绑定 | `callFunction`（`boundArgs` 显式收敛，展示也用转换后值） |
| return | `execStmt('return')` 离开函数前 |
| 数组初始化列表 / 元素赋值 | `declareArray` / `writeCell` |

转换一致性测试：double→int / int→double / int→char 在初始化、赋值、参数、返回、
数组元素五个边界结果完全一致（invariant.test.ts）。

## 【Control Flow】break / continue / goto

- **break**：静态要求 loopDepth>0 或 switchDepth>0；运行时 breakableStack 栈顶
  决定归属（switch 内显示「跳出 switch」）。
- **continue**：静态要求 loopDepth>0（switch 不提供）；运行时自栈顶向下找最近
  循环，事件标注 while/do-while/for，for 的说明指向更新表达式。
- **goto 支持矩阵**（SEMANTIC_MODEL §2.4）：同序列前向/后向 ✅；跳出任意深度 ✅；
  跳过声明 → 补声明为未初始化（读 → E_UNINIT_READ）✅；跳入嵌套块/兄弟块/
  case 体/if 单语句分支 ❌ 编译错误（ISO C 合法，教学取舍，已写入 SUPPORTED_C §3.2）。

## 【Initialization】global / local 行为

| 场景 | 全局（static 存储期） | 局部（auto 存储期） |
| --- | --- | --- |
| `int x;` | 零初始化（0） | 未初始化（读 → E_UNINIT_READ） |
| `double x;` | 0.0 | 未初始化 |
| `int *p;` | NULL（0） | 未初始化 |
| `int a[5];` | 全元素 0 | **全元素未初始化（行为修正）** |
| `int a[5] = {1,2};` | {1,2,0,0,0} | {1,2,0,0,0}（列表存在即前缀+补零） |
| `int a[5] = {};` | 全 0 | 全 0 |
| 初始化策略传递 | `currentStorage='static'` | `'auto'`；后向 goto 重新执行声明按同策略重置 |

## 【Undefined / Unspecified】支持的检测范围

**检测（编译错误 E_UB）**——同一无序列点区域内（`&&`/`||` 序列点分区）：

- R1 双写：`i++ + i++`、`i = i++`、`f(i++, i++)`、`x = (x = 2)`
- R2 读写竞争：`i++ + i`、`a[i] = i++`、`a[i++] = i`、`f(i++, i)`、`f(i) + i++`
- 豁免（C11 6.5.16p3 赋值副作用 sequenced after 值计算）：`x = x + 1`、`x += x`、
  `a[i] = a[i] + 1`、`*p = *p + 1` 合法
- 函数实参之间、数组初始化列表元素之间按无序区域整体分析
  （`printf("%d %d", i, i++)`、`{1, i++, i}` 拒绝）

**不覆盖（SUPPORTED_C §3 已声明）**：函数体内部对全局变量的副作用与调用点表达式
的作用（跨函数分析）；整数溢出环绕；`(i++ && 1) + i` 类「序列点内副作用泄漏到外部」
的罕见模式。

## 【Regression】旧行为变化（均为有意修正，CHANGELOG 对照表声明）

1. 局部 `int a[5];` 声明即全 0 → **元素未初始化**（读取报 E_UNINIT_READ）；
   `tests/array.test.ts` 一处旧断言按新语义更新。
2. 块外使用块内声明 / for 的 i 循环外使用：运行时错误 → **编译错误**。
3. 全局 `int g;` 读取报 E_UNINIT_READ → **零初始化后值为 0**。
4. 函数顶层 break/continue 静态放行 → **编译错误**。
5. `int f(){return 1.9;}` 调用方 1.5 → **1**（类型随返回类型）。
6. UB 表达式（`i++ + i++` 等）确定结果 → **编译错误 E_UB**。
7. goto 跳入嵌套块运行时 E_INTERNAL → **编译错误 E_LABEL**；跳过声明后引用从
   E_UNDEF_VAR 变为 E_UNINIT_READ（`tests/goto.test.ts` 一处注释同步）。
8. switch 内 break 展示文案从「跳出循环」→「跳出 switch」。

21 个内置示例全部无需修改（不依赖任何旧行为）；示例/步骤/快照序列完全不变。

## 【Known Limitations】

1. 差分测试在本地 Windows 优雅跳过（DIFFERENTIAL_COMPILER_UNAVAILABLE），真实
   gcc 比对依赖 CI（ubuntu-latest 预装 gcc）。
2. E_UB 为保守分析：`f(i++, i)`（unspecified 而非 UB）也被拒绝——宁可拒绝不误导；
   跨函数副作用不检测。
3. goto 跳入嵌套块在 ISO C 合法，本版明确不支持（运行时按语句序列冒泡实现）。
4. char 为 0～255 无符号字节（实现定义符号性的教学简化）。
5. `(i++ && 1) + i` 类罕见序列点泄漏模式不在检测范围。
6. 快照仍为每步全量深拷贝（教学规模可控；增量留 v1.2）。
