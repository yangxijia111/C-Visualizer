## 【Root Cause】

为什么修改代码后会出现旧 runResult：

1. `App.tsx` 中编辑器 `onChange` 仅执行 `setSource(v)`——源码状态与运行结果状态
   （`runResult` / `currentStep` / `playing`）之间**没有任何关联约束**。源码变化后，
   旧 `runResult` 原样保留，且继续驱动右侧全部可视化（变量 / 内存 / 调用栈 / 控制流 / 输出）。
2. 当前执行行高亮直接取 `cur.line`——旧运行数据的行号会**错误映射到已修改源码**的同一行号上。
3. 播放控制（上一步 / 下一步 / 播放 / 重新开始 / 时间轴 / 键盘 ←/→/空格）只看
   `currentStep` 与 `total`，不感知源码变化——用户可以继续操作旧状态并误认为对应当前源码。
4. 编译失败分支直接 `setRunResult(null)`，但「编辑后编译失败」时旧结果的语义（保留 or 清除）未定义，
   容易出现「编译失败后旧结果看起来像新结果」的歧义。

教学语义上，这构成「当前编辑器源码」与「右侧可视化结果」不属于同一次运行的误导。

## 【Fix】

Dirty State 设计（纯逻辑提取至 `src/ui/run-state.ts`，与既有 `ui/playback.ts` 同风格）：

| 纯函数 | 职责 |
| --- | --- |
| `nextDirtyState(prev, event)` | 状态转移：`edit → true`；`run-success → false`；`run-fail → 保持`；`load-example → false` |
| `shouldDisablePlayback({busy, parserError, sourceDirty, total})` | 五个播放控制 + 时间轴 + 键盘快捷键的统一禁用判定 |
| `shouldDisableRun({busy, parserError})` | 运行按钮禁用判定（dirty 不影响——重新运行是脱离 stale 的出口） |
| `visibleCurrentLine(sourceDirty, cur)` | dirty 时返回 `null`（旧行号不得映射到已修改源码） |
| `isStaleResult(sourceDirty, runResult)` | stale 横幅显隐：dirty 且旧结果保留 |

App 接入要点：

- **编辑器输入**：`setSource(v)` + `sourceDirty → true` + `setPlaying(false)`
- **运行成功**：`setRunResult(result)` + `setCurrentStep(0)` + `sourceDirty → false`
- **编译失败**：显示 compileErrors；**旧 runResult 保留但继续标记为旧结果**（sourceDirty 不变 →
  播放控制保持禁用）——旧结果不会冒充新结果，修复后可一键「重新运行」
- **加载示例**：完整上下文切换——`runResult = null; currentStep = -1; playing = false;
  compileErrors = null; sourceDirty = false`，等待用户运行

## 【UX】

用户编辑源码后的实际行为（无头 Chrome 实测）：

- 顶部出现 `role="status"` 横幅：**「⚠ 源码已修改，当前可视化结果来自上一次运行，请重新运行。」**
  文字明确说「来自上一次运行」（不使用「数据可能过期」类模糊表述），不依赖颜色传达信息，
  不阻塞编辑器；横幅内提供**「重新运行」按钮**（顶栏「▶ 运行」同样保持可用）
- 编辑器当前执行行高亮立即消失
- 上一步 / 下一步 / 播放 / 重新开始 / 时间轴 / ←/→/空格快捷键全部禁用（键盘按下不步进）
- 变量 / 内存 / 调用栈 / 控制流 / 输出**保留显示旧数据供参考**，但被横幅明确标记为旧结果
- 重新运行成功后：横幅消失、新结果对应新源码、播放控制恢复

## 【Known Limitations】

- 真实存在的限制：
  - stale 判定基于「编辑器输入事件」而非源码内容 diff——撤销回原文（Ctrl+Z 回到与上次运行
    完全相同的内容）仍会保持 stale 标记（宁可多提示，不冒充新结果；不影响正确性）
  - 教学子集范围不变（无 struct / 二维数组 / 动态内存等），首次加载约 800 KB wasm，
    JS bundle 未代码分割——均为 v1.0.1 已知限制，本轮维持
  - 后台标签页 `setInterval` 节流属浏览器行为（播放验证以前台 + 单元测试为准）
- 本轮明确不做（Maintenance Fix 范围约束）：新语言特性、大重构、依赖升级、深色模式、CFG 等
